  Concrete Config Problem
  Your saved runs have:

  model.class_head = hybrid
  loss.match_reliability_weighted = false

  That means L_match and the hybrid prior-similarity class-head path still use the corrupted prior table without reliability gating. So even while L_prior uses repaired Pi_eff, another prior-guided path is still pushing the concept vector according to corrupted prior
  geometry.

  That creates a conflict:

  L_prior says: follow repaired prior.
  L_match / hybrid prior head says: be class-discriminative under corrupted prior.
  L_class says: classify, even if concepts are semantically wrong.

  The model chooses class-discriminative latent concepts, not real concepts.

  What This Means
  The current approach is failing because it only repairs the class-level target, but it does not sufficiently ground image-level concepts, and it may still leak corrupted prior pressure through the matching/class-head path.

  The exact failure chain is:

  1. Reliability detects bad priors reasonably well.
  2. Audit repair makes Pi_eff close to clean prior.
  3. But concept head predictions do not match Pi_eff or true image concepts.
  4. Backbone features separate concepts, so visual signal exists.
  5. Training objective maps those features into wrong/saturated concept outputs.
  6. Classification remains decent because the model can use concept layer as latent class features.

  loss.lambda_match=0.0

  L_audit_concept = BCE(c_hat(x), c)

  weight[m,y_i] = 1 - r[m,y_i]

  Because your diagnostics prove the missing piece:

  Pi_eff is correct at class level,
  features contain concept signal,
  but no loss anchors the concept head to map image features to true concept labels.

  So the next real method should be:

  audit repair + reliability-gated matching + audit concept BCE

  Not more prior repair alone.
